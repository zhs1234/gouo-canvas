# 光构后端接入说明

[English](../en/backend.md) · [文档中心](../README.md)

光构使用基于 One Hub 的 Go 服务统一处理账号、积分、API 中继和云端作品库。`server/` 保留上游许可证、管理端和通用服务商能力；光构公开前端只调用当前产品已接入的接口。

## 1. 请求链路

```text
注册/登录
  POST /api/user/register
  POST /api/user/login
          ↓ 服务端 Cookie
获取用户中继令牌
  GET /api/token/playground
          ↓ 用户专属 token
读取可用模型和报价
  GET /api/gouo/models（X-Gouo-Token）
          ↓ 模型、能力、价格版本
图片请求
  POST /v1/images/generations
  POST /v1/images/edits
  POST /v1/images/variations
          ↓
One Hub 选择渠道、转发上游、记录用量并结算积分
```

浏览器不会收到平台上游 API Key。它只持有当前用户的中继令牌，因此泄漏影响范围被限制在该用户账号、权限和余额内。令牌仍属于敏感信息，不应写入日志或公开分享。

## 2. 本地接入

后端可直接使用 SQLite：

```powershell
Set-Location server
$env:SESSION_SECRET = '<至少 32 位的随机值>'
$env:USER_TOKEN_SECRET = '<另一段至少 32 位的随机值>'
go run .
```

前端 `.env.local`：

```dotenv
VITE_GOUO_BACKEND_URL=
VITE_GOUO_BACKEND_DEV_TARGET=http://127.0.0.1:3000
```

本地 Vite 和生产 Nginx 都应保持同一路由语义：`/api` 负责账号与作品库，`/v1` 负责模型中继。生产环境优先同域部署；只有明确需要跨域时才设置 `VITE_GOUO_BACKEND_URL`，并同时正确配置 Cookie、CORS 和 HTTPS。

同域默认使用 `HttpOnly; SameSite=Strict` 会话。若前端为 `https://app.example.com`、后端为独立站点，前端构建时设置 `VITE_GOUO_BACKEND_URL=https://api.example.net`，后端设置：

```dotenv
GOUO_ALLOWED_ORIGINS=https://app.example.com
SESSION_COOKIE_SECURE=true
SESSION_COOKIE_SAME_SITE=none
```

来源必须是精确的 `http(s)://主机[:端口]`，多个以逗号分隔，不带末尾斜杠、路径或通配符；错误配置会阻止启动。`none` 必须同时启用 Secure 和来源名单。反向代理应覆盖并正确传递 `Host`、`X-Forwarded-Proto`，且 HTTPS 必须贯穿浏览器入口。账号 API 的跨域凭据仅授予名单中的来源；无 Origin 的跨站请求会被拒绝，`none` 模式下携带会话的无 Origin 请求必须有 `Sec-Fetch-Site: same-origin`，只有已有 state 校验的 GitHub/Lark/OIDC GET 回调例外。浏览器禁用第三方 Cookie 时仍应改用同域代理。Compose 已传递这三个环境变量，YAML 对应小写同名配置。

后端按来源 IP 做登录、注册、验证码等限流，并支持令牌 IP 白名单。只有来自 `TRUSTED_PROXIES`（YAML 为 `trusted_proxies`）所列地址的请求才会读取 `X-Forwarded-For` 中的客户端 IP；默认是本机和私有网段，适用于同机或同一容器网络中的 Nginx。反向代理在其他公网地址时，把它的地址或网段加入名单（多个以逗号分隔）；后端直接对公网提供服务时设为空。经 Cloudflare 等平台访问时，可改用 `trusted_header`（如 `CF-Connecting-IP`）。注意后端只要看到这个头就直接采用，不检查请求来源：必须保证源站只能经该平台访问（防火墙只放行平台网段，`PUBLIC_PORT` 绑定本机或内网），否则任何人直连源站并自带该头即可伪造 IP，绕过限流和令牌 IP 白名单。

## 3. 管理后台

管理后台由后端提供，默认地址为 `http://127.0.0.1:3000/panel`。空数据库首次启动会创建 `root` / `123456`，必须在开放网络访问前修改。

后台仅限管理员登录：普通用户在后台登录会被拒绝，已登录的普通用户打开后台会被退出；后台登录页不显示注册入口。普通用户只使用光构客户端。后台的余额、日志、统计、图表和输入提示统一按积分显示（1 元 = 100 积分），服务端记账方式见[第 4 节](#4-按模型图片计费)。

光构专用功能集中在左侧“光构”菜单下：光构设置、光构模型、图片账务和光构存储。

### 3.1 光构设置

![光构设置](../images/screenshots/panel-gouo-settings.webp)

“光构设置”集中管理直接作用于客户端的设置。普通管理员即可修改（系统设置接口仍只允许 root）；用户切回客户端页面或刷新后生效：

- **创作页公告**：显示在客户端创作页顶部，单行、最多 200 字；留空时显示默认介绍。用户关闭后，公告内容变化时会再次显示。
- **默认图片模型**：从已启用的模型中选择，见[第 4 节](#4-按模型图片计费)。
- **兑换码获取说明**、**客服联系方式**：在用户中心的兑换页和“充值与账务帮助”展示。两项默认留空，未填写时界面提示尚未配置。
- **开放画布**、**开放 Agent**：关闭后客户端隐藏对应入口（创作页模式切换、侧栏“我的画布”或“创作会话”、画布里的 Agent 按钮），直接访问对应地址会回到创作页；已保存的画布和会话保留。关闭 Agent 时 Agent 模型目录返回为空。前端构建变量 `VITE_CANVAS_ENABLED`、`VITE_AGENT_ENABLED` 仍是上限：构建时关闭的入口，后台无法打开。
- **一次最多生成张数**：1–10 张，限制客户端一次提交的图片总数，生成页、画布和 Agent 都受此限制，每张仍按单图请求计费。它是客户端的提交限制；单个 HTTP 请求的张数由各模型的“单次请求最多输出张数”约束。
- **默认 Agent 模型**：新对话默认使用的对话模型，从满足 Agent 条件的模型中选择（见 3.8 第 10 步）；未设置或对用户不可用时使用目录中的第一个。
- **Agent 附加提示词**：最多 4000 字，附加在内置规则之后，用于补充语气、品牌或业务要求，不能放宽计费确认、工具和安全规则；在新的一轮对话中生效。
- **云端作品库**：开放开关、默认每用户空间（GB）、单文件上传上限（1–100 MB）和回收站保留天数（1–30 天），见[第 5 节](#5-云端作品库)。调高上传上限时，同步调整 Nginx 的 `client_max_body_size`（部署模板为 32 MB）和 CDN 限制。

页面下方显示当前的注册和密码登录状态。这两个开关在“设置 → 系统设置”中修改（仅 root），也会同步给客户端：关闭注册后，客户端点“免费注册”显示“暂未开放注册”，登录页不再显示注册链接；关闭密码登录后，登录页提示已暂停登录。

### 3.2 光构模型

![光构模型](../images/screenshots/panel-gouo-models.webp)

“光构模型”列出已定价或已配置在渠道上的模型，显示售价、能力、支持它的渠道和分组，以及客户端是否可见及原因。可以直接启用、编辑、下架、设为默认或清除默认模型。页面分“图片模型”和“Agent 模型”两个标签页，后台按模型类型分开列出：已启用的图片模型和已上架的 Agent 模型以当前状态为准，其余模型中，模型资料声明只输出图片、或名称含 image、dall-e、flux 等字样的是图片模型；模型资料声明输出文本、或名称是 gpt-5、claude、gemini、deepseek、qwen、glm、kimi、豆包等近期主流文本模型的是文本模型；仍判断不了的，按 token 计费的视为文本模型，其余在两边都列出。同一个模型不能同时作为图片模型和 Agent 模型，需要先在另一边下架；价格管理里同样不能把已上架的 Agent 模型启用为图片模型。默认只列出本类、有渠道的模型，打开“显示全部模型”可查看其余模型，另一类的模型会带上类型标注。

Agent 模型的价格按“积分/百万 token”填写，在这里保存价格后不再随上游价格同步变化；只下架或只改排序、回复上限不会锁定价格。按次计费的模型显示每次请求的积分，不会出现在客户端 Agent 中（客户端按每百万 token 显示价格）；填写价格会改为按 token 计费，需要同时填写输入和输出价格，两个价格都留空则保持按次计费、只保存其他字段。

![编辑光构模型](../images/screenshots/panel-gouo-model-edit.webp)

编辑窗口按积分填写每张售价（下方提示折合的人民币），设置单次请求最多输出张数，以及是否支持参考图和遮罩编辑（遮罩编辑需要同时支持参考图）。下架时沿用原售价。价格管理的单模型编辑窗口里有同样的光构配置。

### 3.8 首次配置顺序

1. 新建独立的日常管理员账号。
2. 添加 OpenAI 或兼容图片渠道，API Key 只保存在渠道中。
3. 配置实际图片模型与渠道映射，在“光构模型”启用模型并设置积分售价、参考图/遮罩能力和输出数量上限。客户端直接显示模型 ID，与请求使用的公开模型 ID 一致，不另外配置展示名称。
4. 在“光构设置”设置默认图片模型、兑换码获取说明和客服联系方式，按需发布公告。
5. 验证 generations、edits 和 variations 三条路由。
6. 核对不同模型售价、成功扣费、失败退款、价格变化确认和余额不足拒绝。
7. 设置新用户赠送（输入框旁显示折合积分）、兑换码、注册策略和限流。
8. 若计划使用在线支付，先完成支付渠道、回调验签、异常订单和对账测试，再开放入口。支付回调始终按网关的当前配置验签：更换商户（app_id、商户号或平台公钥属于另一个商户）时，请新建网关并停用旧网关，旧网关保留到其订单全部完成或关闭；否则改配置前创建的订单收到原商户回调时会验签失败、无法入账。
9. 在“光构存储”确认资产目录可写，并检查用户空间。
10. 如需 Agent，在“模型详情”为文本模型配置 `output_modalities` 含 `"text"`、`tags` 含 `"tools"`（支持视觉时 `input_modalities` 含 `"image"`），并为其定价和配置支持流式工具调用的渠道。

### 3.9 注册验证与 Turnstile

注册页按后端状态显示邮箱验证码和 Cloudflare Turnstile；状态加载失败时显示重试，不会跳过必需的验证。在后台设置 `TurnstileCheckEnabled`、`TurnstileSiteKey`、`TurnstileSecretKey`，并在 Cloudflare 配置实际的前端域名。公开 site key 用于注册、发送邮箱验证码、发送密码重置邮件和用户中心绑定邮箱的验证组件；secret key 只留在服务端。验证过期或失败可以重试，提交后会刷新挑战。自定义 CSP 需要允许 `https://challenges.cloudflare.com` 的脚本和 frame。令牌随请求交给后端现有的 Siteverify 中间件校验，不能只信任前端的成功回调。参见[客户端接入](https://developers.cloudflare.com/turnstile/get-started/client-side-rendering/)和[服务端校验](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)。光构公开登录页不提供 OAuth 登录入口。

Turnstile 沿用后端已有的会话策略：首次校验成功后，session 中写入 `turnstile=true`，同一会话的后续请求复用这一状态，不会每次调用 Siteverify。前端每次请求后刷新 token，并不改变这一服务端策略。

产品模式的客户端不导入链接里的 `apiUrl`、`apiKey` 等服务地址参数和远程配置地址，只把这些参数从地址栏清掉。

## 4. 按模型图片计费

图片生成、编辑和变体接口按公开模型的人民币售价收费，每次成功 HTTP 请求扣费。售价、启用状态、能力和数量上限保存在现有 `Price` 表；同一模型的尺寸、质量及生成/编辑同价，不叠加用户组倍率，渠道映射不改变售价。编辑和变体接口只接受 `multipart/form-data`：参考图按表单里 `image`、`image[]` 文件的实际数量计入模型的参考图上限，其他字段名的文件会被拒绝。

以下旧配置仅用于首次迁移默认模型，此后改价使用管理后台，不靠重启覆盖：

```dotenv
GOUO_IMAGE_PRICE_CNY=0.10
GOUO_IMAGE_MODEL=gpt-image-2
```

- 对用户统一使用积分：**1 元 = 100 积分**。客户端的余额、单价、预计扣费、使用记录与 CSV 都按积分显示；后台“光构模型”、价格编辑、光构计费记录按积分填写和展示，兑换码弹窗和用户“增减积分”可直接按积分填写并自动换算额度；后台其余余额、日志、统计、图表和设置项提示也都按积分显示。新写入的账务日志（兑换、赠送、管理员调整、在线充值）正文和余额提醒邮件同样使用积分；客户端不展示旧日志里按美元或原始额度书写的正文，金额仍按积分单独显示。服务端记账不变，仍保存人民币售价并按下面的公式换算额度，因此切换无需迁移数据，已有余额只是换算显示。
- 首次迁移仅启用旧默认模型及其售价，参考图/遮罩能力开启，单次输出上限为 **1 张**；需要多图时管理员应核对上游成本后提高上限。该上限只约束单个 HTTP 请求的 `n`，不限制产品客户端一次生成的总张数（客户端拆成单图请求）。迁移不修改账号余额和历史作品，不自动开放其他模型；下架或删除默认模型后重启不会重新开放。
- 客户端可用的模型在“光构 → 光构模型”集中管理，见[第 3.2 节](#32-光构模型)。
- 客户端默认模型由“光构模型”页面的“设为默认”或“光构设置”的“默认图片模型”控制：用户没有手动选过模型、或所选模型已下架时，使用该模型；留空或该模型对用户不可用时，使用模型目录中的第一个。管理员修改后，对没有手动选过模型的用户立即生效。客户端不预设模型，模型目录加载前不选中任何模型。用户手动选择按账号记忆，登录/令牌刷新不覆盖；任务和重试固定原模型。
- `GET /api/gouo/models` 需要登录 Cookie 和当前账号图片令牌 `X-Gouo-Token`，目录取启用配置、有效报价、实际令牌模型白名单、分组可用渠道的交集。无合法价格或模型下架时禁止调用，不回退通用计费。
- 客户端在提交时传 `X-Gouo-Price-Version`，报价或能力变化返回 `409 image_price_changed`；刷新目录核对价格后重新提交。产品模式每次重试都会先确认新请求的费用，价格变化时显示新价格。普通非产品 API 令牌可省略版本，仍使用请求开始时快照计费。
- 服务端以 `ceil(人民币售价 / PaymentUSDRate × QuotaPerUnit)` 换算额度，事务条件更新余额与令牌额度，成功结算、后端确认失败退款；渠道重试共用一次预扣。历史日志保存公开模型、单价、单位、价格版本和实际额度，用户中心和 CSV 使用单价快照；累计消费仅为已消耗额度按当前兑换率折合。
- 光构产品客户端把 n 张拆成 n 个单图请求，每个成功的请求单独收费（按成功张数计费），一次最多 10 张。直接调用 API 时，单个 HTTP 请求在模型输出上限内要求多张图只收费一次。纯前端兼容模式同样可能拆成多个请求，分别收费。
- 价格同步和通用批量调价保留已启用的光构配置；光构配置在单模型编辑窗口修改。用户售价独立于上游成本，运营方必须核对真实账单。

图片请求在预扣事务内写入持久账本。上游等待上限为 15 分钟；主节点启动及每分钟检查中断记录，超过 20 分钟仍未发送的请求自动退款，已发送但结果未知的请求进入“待核对”，避免误退已成功的生成。结算或退款与额度、统计和日志同事务提交，重复处理不会重复变动余额。

浏览器超时、输出下载或本地保存失败不代表已退款。用户在“用户中心 → 使用记录 → 图片请求状态”核对，管理员在“光构 → 图片账务”按请求编号核查渠道记录，填写依据后选择结算或退款。重试会新建收费请求，不会恢复原结果。升级前备份数据库；旧版本没有账本的历史中断不能自动追溯，需结合旧日志人工处理。

## 5. 云端作品库

主要配置：

```dotenv
GOUO_CLOUD_LIBRARY_ENABLED=true
GOUO_ASSET_DIR=/data/gouo-assets
GOUO_ASSET_USER_QUOTA_BYTES=2147483648
GOUO_ASSET_MAX_FILE_BYTES=26214400
GOUO_ASSET_MAX_TASK_FILES=32
```

其中作品库开关、默认用户空间和单文件上限也可以在后台“光构 → 光构设置”修改：环境变量只是初始值，管理员在后台保存过之后以数据库中的值为准，修改即时生效（多实例最多 1 分钟同步）。`GOUO_ASSET_DIR` 和 `GOUO_ASSET_MAX_TASK_FILES` 仍只能通过环境变量配置。

默认含义：

- 单用户空间 2 GiB。
- 单文件最大 25 MiB。
- 单任务最多关联 32 个资产。
- 同一用户内按 SHA-256 去重；不同用户仍保持独立鉴权关系。

生成成功的图片在出图时由服务端直接写入作品库；浏览器只补交任务元数据、参考图和遮罩，不再上传缩略图和流式中间图。画布与 Agent 会话按文档保存到数据库（单文档不超过 4 MB，最多关联 2000 张图片）。图片通过鉴权接口读取，`GOUO_ASSET_DIR` 不能直接暴露为 Nginx 静态目录。

空间配额和单文件 25 MiB 上限只约束用户上传的参考图、遮罩等；服务端保存的已付费生成图不受配额限制（单张最大 64 MB），因此已用空间可能超过配额。图片结果另在 `GOUO_ASSET_DIR/image-results` 缓存 24 小时（总量上限 4 GB，单个结果 256 MB），供中断后取回原结果，容量规划和备份需把它算在内。

删除的作品、画布、会话和收藏夹进入回收站，默认保留 3 天（可在“光构设置”改为 1–30 天），期间可恢复并继续占用空间；之后由主节点每小时执行的清理任务彻底删除记录和不再被引用的图片文件。已删除账号的云端数据按同样期限清除。缩短保留天数后，已超过新期限的内容会在下一次清理时删除。

本地文件资产模式只适合单后端实例。多实例必须挂载同一个共享文件系统；否则数据库记录可能指向另一实例看不到的文件。对象存储尚未在光构专用作品库中完成接入。

## 6. 数据库、Redis 与备份

- 本地开发可使用 SQLite。
- 公开生产环境使用 MySQL 或 PostgreSQL。
- 多实例共享同一数据库、Redis、签名密钥和资产存储。
- 多实例时只让一个实例作为主节点（其余设 `NODE_TYPE=slave`），定时任务（扣费恢复、回收站清理）只在主节点运行。模型价格和光构模型上下架在其他实例上最多 1 分钟后生效，期间按旧价格版本提交的请求会收到“价格已更新”，刷新页面即可。
- Redis 是缓存与协调层，不能代替数据库备份。
- 数据库与 `GOUO_ASSET_DIR` 必须在同一维护窗口成对备份和恢复。
- `SESSION_SECRET`、`USER_TOKEN_SECRET` 和生产环境文件要加密备份。

只恢复数据库会得到缺失图片的作品记录；只恢复资产目录会得到没有归属关系的文件。

## 7. 关键接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/status` | 后端状态与客户端设置（注册与密码登录开关、公告、兑换说明、客服联系方式、邮箱与 Turnstile 配置） |
| `GET /api/user/self` | 当前用户信息、余额（`balance_cny`）和积分换算率；旧 image_price_cny 不作为模型报价 |
| `GET /api/gouo/models` | 当前图片令牌可用模型、售价、能力、数量上限和价格版本 |
| `POST /api/user/login` | 登录 |
| `POST /api/user/register` | 注册 |
| `GET /api/token/playground` | 当前用户专属图片中继令牌 |
| `POST /api/user/topup` | 兑换码充值 |
| `GET /api/log/self` | 当前用户使用记录 |
| `GET /api/gouo/storage` | 云端空间信息 |
| `POST /api/gouo/assets` | 上传账号资产 |
| `GET /api/gouo/tasks`、`GET /api/gouo/collections` | 按游标分页拉取作品和收藏夹（`hidden=true` 为回收站） |
| `PUT /api/gouo/tasks/:clientTaskId` | 写入或更新任务 |
| `PATCH /api/gouo/tasks/:clientTaskId/meta` | 补交服务端已保存作品的元数据 |
| `POST /api/gouo/tasks/:id/hide`、`/restore` | 移入回收站、恢复作品 |
| `PUT /api/gouo/collections/:id` | 写入或更新收藏夹（`/hide`、`/restore` 同上） |
| `/api/gouo/canvases[/:id]`、`/api/gouo/conversations[/:id]` | 画布和 Agent 会话文档的列表、读取、保存、隐藏与恢复 |
| `GET /api/gouo/image-charges` | 当前用户的图片扣费记录 |
| `GET /api/gouo/image-results` | 按原请求编号取回已付费的图片结果 |
| `GET /api/gouo/agent/models` | 当前用户可用的 Agent 模型 |
| `GET/PUT /api/gouo/admin/settings` | 管理员读写光构客户端设置（公告、默认图片模型、兑换说明、客服联系方式） |
| `GET/PUT /api/gouo/admin/models` | 管理员查看和修改光构模型的售价、能力与上下架 |
| `GET /api/gouo/admin/image-charges`、`POST …/:id/resolve` | 管理员查看图片账务并核对待处理请求 |
| `GET /api/gouo/admin/storage[/users…]`、`PUT …/users/:id/quota` | 管理员查看存储用量、浏览用户作品、调整用户配额 |

所有用户数据接口都必须在服务端校验登录身份和资源所有权，不要仅依赖前端隐藏按钮。

## 8. 当前边界

- 光构公开前端已经提供登录、注册、用户中心、兑换码、使用记录、云端作品库、画布和 Agent。
- 在线支付只有在 One Hub 侧配置完成并经过回调、重复通知、失败和对账测试后才可作为正式能力。
- 客户端按非流式响应调用图片端点。
- `server/docs/` 描述的是上游 One Hub 通用能力，不自动代表光构前端已经开放对应入口。
