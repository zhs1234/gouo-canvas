# 光构后端接入说明

[English](../en/backend.md) · [文档中心](../README.md)

光构使用基于 New API 的 Go 服务统一处理账号、积分、API 中继和云端作品库。`server/` 保留上游许可证、管理端和通用服务商能力；光构公开前端只调用当前产品已接入的接口。

## 1. 请求链路

```text
注册/登录
  POST /api/user/register
  POST /api/user/login
          ↓ 服务端 Cookie
获取用户中继令牌
  GET /api/gouo/token
          ↓ 用户专属 token
读取可用模型和报价
  GET /api/gouo/models
          ↓ 模型、能力、价格版本
图片请求
  POST /v1/images/generations
  POST /v1/images/edits
          ↓
New API 选择渠道、转发上游、按模型定价预扣并结算积分
```

浏览器不会收到平台上游 API Key。它只持有当前用户的中继令牌（数据库中每个用户一个专用 New API 令牌），因此泄漏影响范围被限制在该用户账号、权限和余额内。令牌仍属于敏感信息，不应写入日志或公开分享。

## 2. 本地接入

后端可直接使用 SQLite：

```powershell
Set-Location server
$env:SESSION_SECRET = '<至少 32 位的随机值>'
go run .
```

前端 `.env.local`：

```dotenv
VITE_GOUO_BACKEND_URL=
VITE_GOUO_BACKEND_DEV_TARGET=http://127.0.0.1:3000
```

本地 Vite 和生产 Nginx 都应保持同一路由语义：`/api` 负责账号与作品库，`/v1` 负责模型中继。生产环境优先同域部署；只有前后端在同一站点的不同子域时才设置 `VITE_GOUO_BACKEND_URL`。

登录会话 Cookie 固定为 `HttpOnly; SameSite=Strict`，跨站（不同注册域名）的前端拿不到会话，因此不支持跨站部署。通过 HTTPS 访问时设置 `SESSION_COOKIE_SECURE=true`，并在 `SESSION_COOKIE_TRUSTED_URL` 填写对外访问的完整 origin（只能是 https，多个以逗号分隔）；两者必须同时设置，否则后端拒绝启动。反向代理应覆盖并正确传递 `Host`、`X-Forwarded-Proto`。

后端按来源 IP 做登录、注册、验证码等限流，并支持令牌 IP 白名单。只有来自 `TRUSTED_PROXIES`（YAML 为 `trusted_proxies`）所列地址的请求才会读取 `X-Forwarded-For` 中的客户端 IP；默认是本机和私有网段，适用于同机或同一容器网络中的 Nginx。反向代理在其他公网地址时，把它的地址或网段加入名单（多个以逗号分隔）；后端直接对公网提供服务时设为空。经 Cloudflare 等平台访问时，可改用 `trusted_header`（如 `CF-Connecting-IP`）。注意后端只要看到这个头就直接采用，不检查请求来源：必须保证源站只能经该平台访问（防火墙只放行平台网段，`PUBLIC_PORT` 绑定本机或内网），否则任何人直连源站并自带该头即可伪造 IP，绕过限流和令牌 IP 白名单。

## 3. 管理后台

管理后台由后端提供，默认地址为 `http://127.0.0.1:3000`。空数据库首次启动会创建 `root` / `123456`，必须在开放网络访问前修改。

后台仅限管理员登录：普通用户在后台登录会被拒绝，已登录的普通用户打开后台会被退出；后台登录页不显示注册入口。普通用户只使用光构客户端。后台的余额、日志、统计、图表和输入提示统一按积分显示（1 元 = 100 积分），服务端记账方式见[第 4 节](#4-按模型图片计费)。

光构专用功能集中在左侧“光构”菜单下：光构设置、光构存储和图片账务。客户端用到的模型在 New API 原生的“模型管理”和模型定价里配置，见[第 3.2 节](#32-客户端模型)。

### 3.1 光构设置

![光构设置](../images/screenshots/panel-gouo-settings.webp)

创作页顶部的公告使用 New API 原生的控制台公告（“设置 → 控制台”中开启并添加公告）：客户端显示最新一条公告的第一行，未开启或没有公告时显示默认介绍；用户关闭后，公告内容变化时会再次显示。

“光构设置”集中管理直接作用于客户端的设置。普通管理员即可修改（系统设置接口仍只允许 root）；用户切回客户端页面或刷新后生效：

- **默认图片模型**：从已启用的模型中选择，见[第 4 节](#4-按模型图片计费)。
- **兑换码获取说明**、**客服联系方式**：在用户中心的兑换页和“充值与账务帮助”展示。两项默认留空，未填写时界面提示尚未配置。
- **开放画布**、**开放 Agent**：关闭后客户端隐藏对应入口（创作页模式切换、侧栏“我的画布”或“创作会话”、画布里的 Agent 按钮），直接访问对应地址会回到创作页；已保存的画布和会话保留。关闭 Agent 时 Agent 模型目录返回为空。前端构建变量 `VITE_CANVAS_ENABLED`、`VITE_AGENT_ENABLED` 仍是上限：构建时关闭的入口，后台无法打开。
- **一次最多生成张数**：1–10 张，限制客户端一次提交的图片总数，生成页、画布和 Agent 都受此限制，每张仍按单图请求计费。它是客户端的提交限制；单个 HTTP 请求的张数由各模型的“单次请求最多输出张数”约束。
- **默认 Agent 模型**：新对话默认使用的对话模型，从满足 Agent 条件的模型中选择（见 3.8 第 10 步）；未设置或对用户不可用时使用目录中的第一个。
- **Agent 附加提示词**：最多 4000 字，附加在内置规则之后，用于补充语气、品牌或业务要求，不能放宽计费确认、工具和安全规则；在新的一轮对话中生效。
- **云端作品库**：开放开关、默认每用户空间（GB）、单文件上传上限（1–100 MB）和回收站保留天数（1–30 天），见[第 5 节](#5-云端作品库)。调高上传上限时，同步调整 Nginx 的 `client_max_body_size`（部署模板为 32 MB）和 CDN 限制。

页面下方显示当前的注册和密码登录状态。这两个开关在“设置 → 系统设置”中修改（仅 root），也会同步给客户端：关闭注册后，客户端点“免费注册”显示“暂未开放注册”，登录页不再显示注册链接；关闭密码登录后，登录页提示已暂停登录。

### 3.2 客户端模型

客户端的图片模型和 Agent 模型都直接读 New API 原生的模型资料，没有单独的光构模型页：

- **图片模型**：New API 识别为图片生成的模型（按模型名推断，或在“模型管理”里为模型声明 image-generation 端点），且在当前用户分组里有可用渠道。模型名即显示名称，说明取“模型管理”里填写的描述。
- **图片编辑能力**：在“模型管理”给模型加标签。带 `edit` 才能用参考图编辑，带 `edit` 和 `mask` 才能用遮罩编辑。客户端开放 1K/2K/4K 全部分辨率档位，单次请求输出 1 张（客户端把多张拆成单图请求）。
- **Agent 模型**：带 `tools` 标签、已在模型定价里设置价格、且当前用户分组有可用渠道的文本模型；再加 `vision` 标签即可理解上传的图片。渠道必须实际支持流式工具调用。
- 在“模型管理”里停用的模型不会出现在客户端。

修改标签或价格后，客户端提交时会收到“价格或能力已更新”，刷新后重新确认即可。

### 3.8 首次配置顺序

1. 新建独立的日常管理员账号。
2. 添加 OpenAI 或兼容图片渠道，API Key 只保存在渠道中。
3. 配置实际图片模型与渠道映射，在 New API 的模型定价中为它设置价格，在“模型管理”按需加上 `edit`、`mask` 标签和描述。
4. 在“光构设置”设置默认图片模型、兑换码获取说明和客服联系方式，按需在控制台公告中发布公告。
5. 验证 generations 和 edits 两条路由（variations 未实现）。
6. 核对不同模型售价、成功扣费、失败退款、价格变化确认和余额不足拒绝。
7. 设置新用户赠送（输入框旁显示折合积分）、兑换码、注册策略和限流。
8. 若计划使用在线支付，先完成支付渠道、回调验签、异常订单和对账测试，再开放入口。支付回调始终按网关的当前配置验签：更换商户（app_id、商户号或平台公钥属于另一个商户）时，请新建网关并停用旧网关，旧网关保留到其订单全部完成或关闭；否则改配置前创建的订单收到原商户回调时会验签失败、无法入账。
9. 在“光构存储”确认资产目录可写，并检查用户空间。
10. 如需 Agent，在“模型管理”给文本模型加 `tools` 标签（能识图再加 `vision`），并为其定价和配置支持流式工具调用的渠道。

### 3.9 注册验证与 Turnstile

注册页按后端状态显示邮箱验证码和 Cloudflare Turnstile；状态加载失败时显示重试，不会跳过必需的验证。在后台设置 `TurnstileCheckEnabled`、`TurnstileSiteKey`、`TurnstileSecretKey`，并在 Cloudflare 配置实际的前端域名。公开 site key 用于注册、发送邮箱验证码、发送密码重置邮件和用户中心绑定邮箱的验证组件；secret key 只留在服务端。验证过期或失败可以重试，提交后会刷新挑战。自定义 CSP 需要允许 `https://challenges.cloudflare.com` 的脚本和 frame。令牌随请求交给后端现有的 Siteverify 中间件校验，不能只信任前端的成功回调。参见[客户端接入](https://developers.cloudflare.com/turnstile/get-started/client-side-rendering/)和[服务端校验](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)。光构公开登录页不提供 OAuth 登录入口。

Turnstile 沿用后端已有的会话策略：首次校验成功后，session 中写入 `turnstile=true`，同一会话的后续请求复用这一状态，不会每次调用 Siteverify。前端每次请求后刷新 token，并不改变这一服务端策略。

产品模式的客户端不导入链接里的 `apiUrl`、`apiKey` 等服务地址参数和远程配置地址，只把这些参数从地址栏清掉。

## 4. 按模型图片计费

图片生成和编辑接口使用 New API 自身的模型定价（按次价格、模型倍率或阶梯计费表达式均可），在 New API 的定价设置里修改；用户组倍率等 New API 规则照常生效。光构的额外校验只作用于光构客户端（平台令牌）的图片请求，其他 API 调用按 New API 原生行为处理。客户端可选 1K/2K/4K 分辨率，服务端拒绝超过 4K 的尺寸。编辑接口只接受 `multipart/form-data`，只允许 `image`、`image[]` 和 `mask` 字段的文件。`/v1/images/variations` 未实现。

- 对用户统一使用积分：**1 元 = 100 积分**。客户端的余额、单价、预计扣费、使用记录与 CSV 都按积分显示。
- 客户端可用的模型来自 New API 原生模型资料，见[第 3.2 节](#32-客户端模型)。
- 客户端默认模型由“光构设置”的“默认图片模型”控制：用户没有手动选过模型、或所选模型已下架时，使用该模型；留空或该模型对用户不可用时，使用模型目录中的第一个。客户端不预设模型，模型目录加载前不选中任何模型。用户手动选择按账号记忆；任务和重试固定原模型。
- `GET /api/gouo/models` 需要登录 Cookie，目录取已启用且当前账号分组可用的模型。
- 客户端在提交时传 `X-Gouo-Price-Version`。版本由 New API 生效定价和光构能力配置计算，任一变化都会返回 `409 image_price_changed`，刷新目录核对价格后重新提交；改名、改说明或调整顺序不影响版本。产品客户端每次重试都会先确认新请求的费用。
- 光构产品客户端把 n 张拆成 n 个单图请求，每个成功的请求单独收费。直接调用 API 时，单个 HTTP 请求在模型输出上限内要求多张图按 New API 规则计费。
- 用户售价独立于上游成本，运营方必须核对真实账单。

图片请求在预扣时写入持久账本（按 `X-Gouo-Request-Id` 去重）。主节点每分钟检查中断记录，超过 20 分钟仍未结算的请求自动退款。上游结果未知时也直接退款，不换渠道重试，这类请求的上游费用由平台承担。结算或退款与额度、统计和日志同事务提交，重复处理不会重复变动余额。

服务端已结算的请求，结果会暂存供浏览器断线后取回；浏览器本地保存失败不会退款。用户在“用户中心 → 使用记录”的积分明细查看扣费和退款，管理员在“光构 → 图片账务”按请求编号查询。重试会新建收费请求，不会恢复原结果。升级前备份数据库。

## 5. 云端作品库

主要配置（只有这两项来自环境变量）：

```dotenv
GOUO_ASSET_DIR=/data/gouo-assets
GOUO_ASSET_MAX_TASK_FILES=32
```

作品库开关、默认用户空间、单文件上限和回收站保留天数在后台“光构 → 光构设置”修改，修改即时生效（多实例最多 1 分钟同步）。

默认含义：

- 单用户空间 2 GiB。
- 单文件最大 25 MiB。
- 单任务最多关联 32 个资产。
- 同一用户内按 SHA-256 去重；不同用户仍保持独立鉴权关系。

生成成功的图片在出图时由服务端直接写入作品库；浏览器只补交任务元数据、参考图和遮罩，不再上传缩略图和流式中间图。画布与 Agent 会话按文档保存到数据库（单文档不超过 4 MB，最多关联 2000 张图片）。图片通过鉴权接口读取，`GOUO_ASSET_DIR` 不能直接暴露为 Nginx 静态目录。

空间配额和单文件 25 MiB 上限只约束用户上传的参考图、遮罩等；服务端保存的已付费生成图不受配额限制（单张最大 64 MB），因此已用空间可能超过配额。图片结果另在 `GOUO_ASSET_DIR/image-results` 缓存 24 小时（总量上限 4 GB，单个结果 256 MB），供中断后取回原结果，容量规划和备份需把它算在内。

删除的作品、画布、会话和收藏夹进入回收站，默认保留 3 天（可在“光构设置”改为 1–30 天），期间可恢复并继续占用空间；之后由主节点每小时执行的清理任务彻底删除记录和不再被引用的图片文件。已删除账号的云端数据按同样期限清除。缩短保留天数后，已超过新期限的内容会在下一次清理时删除。

本地文件资产模式只适合单后端实例。多实例必须挂载同一个共享文件系统；否则数据库记录可能指向另一实例看不到的文件。对象存储尚未在光构专用作品库中完成接入。

## 6. 数据库、Redis 与备份

- 本地开发可使用 SQLite。
- 公开生产环境使用 MySQL 或 PostgreSQL。
- 多实例共享同一数据库、Redis、签名密钥和资产存储。
- 多实例时只让一个实例作为主节点（其余设 `NODE_TYPE=slave`），定时任务（扣费恢复、回收站清理）只在主节点运行。
- Redis 是缓存与协调层，不能代替数据库备份。
- 数据库与 `GOUO_ASSET_DIR` 必须在同一维护窗口成对备份和恢复。
- `SESSION_SECRET`（以及单独设置时的 `CRYPTO_SECRET`）和生产环境文件要加密备份。

只恢复数据库会得到缺失图片的作品记录；只恢复资产目录会得到没有归属关系的文件。

## 7. 关键接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/status` | 后端状态与客户端设置（注册与密码登录开关、控制台公告、兑换说明、客服联系方式、邮箱与 Turnstile 配置） |
| `GET /api/user/self` | 当前用户信息和余额 |
| `GET /api/gouo/models` | 当前账号可用的图片模型、计费方式、能力、数量上限和价格版本 |
| `POST /api/user/login` | 登录 |
| `POST /api/user/register` | 注册 |
| `GET /api/gouo/token` | 当前用户专属中继令牌 |
| `POST /api/user/topup` | 兑换码充值 |
| `GET /api/log/self` | 当前用户使用记录 |
| `GET /api/gouo/storage` | 云端空间信息 |
| `POST /api/gouo/assets` | 上传账号资产 |
| `GET /api/gouo/tasks`、`GET /api/gouo/collections` | 按游标分页拉取作品和收藏夹（`hidden=true` 为回收站） |
| `PUT /api/gouo/tasks/:clientTaskId` | 写入或更新任务 |
| `PATCH /api/gouo/tasks/:clientTaskId/meta` | 补交服务端已保存作品的元数据 |
| `POST /api/gouo/tasks/:id/hide`、`/restore` | 移入回收站、恢复作品 |
| `PUT /api/gouo/collections/:id` | 写入或更新收藏夹（`/hide`、`/restore` 同上） |
| `/api/gouo/canvases[/:id]`、`/api/gouo/conversations[/:id]` | 画布和 Agent 会话文档的列表、读取、保存、隐藏与恢复 |
| `GET /api/gouo/image-results` | 按原请求编号取回已付费的图片结果 |
| `GET /api/gouo/agent/models` | 当前用户可用的 Agent 模型 |
| `POST /pg/chat/completions` | Agent 对话（New API 原生 Playground，登录会话鉴权，带 `X-Gouo-Agent` 头） |
| `GET/PUT /api/gouo/admin/settings` | 管理员读写光构客户端设置（默认图片模型、兑换说明、客服联系方式等） |
| `GET /api/gouo/admin/models` | 管理员查看会出现在客户端的图片模型和 Agent 模型，用于选择默认模型 |
| `GET /api/gouo/admin/image-charges` | 管理员查看图片预扣账本 |
| `GET /api/gouo/admin/storage[/users…]`、`PUT …/users/:id/quota` | 管理员查看存储用量、浏览用户作品、调整用户配额 |

所有用户数据接口都必须在服务端校验登录身份和资源所有权，不要仅依赖前端隐藏按钮。

## 8. 当前边界

- 光构公开前端已经提供登录、注册、用户中心、兑换码、使用记录、云端作品库、画布和 Agent。
- 在线支付只有在 New API 侧配置完成并经过回调、重复通知、失败和对账测试后才可作为正式能力。
- 客户端按非流式响应调用图片端点。
- `server/docs/` 描述的是上游 New API 通用能力，不自动代表光构前端已经开放对应入口。
