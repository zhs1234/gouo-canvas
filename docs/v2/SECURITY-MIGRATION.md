# 安全、订阅与迁移

## 认证与密钥

只复用现有认证设施，不在浏览器复制 API key/token 的旧 Playground 模式。所有 V2 job 从 `/api/studio` 进入；查验旧 `/v1`、`/api/token/playground`、用户令牌是否能绕过 V2 套餐。不能用一个管理员/无限 token 下发所有用户。内部服务 token 必须限定作用域、渠道与额度，仅 worker 可用。

生产所有 cookie 写操作做 CSRF/Origin 校验，Session 固定、安全标记、注销与封禁及时生效。账号切换清除服务端数据缓存和未提交的私有草稿。普通用户不能查询他人资产；管理访问需审计。

## 素材与上游地址

上传检查 MIME 与真实文件头、解码尺寸/像素、字节数、文件名，不允许任意路径/未经清洗 SVG。对象存储私有，短期签名/服务器授权下载，公共缓存不能泄漏用户图片。导出防 Canvas 跨源污染。管理员也不能配置可访问元数据/内网/回环的任意抓取 URL；DNS、重定向、连接目的地址都需校验，限制下载体积/时间。

第三方模型获得哪些商品图要有明确渠道政策。重试不能悄悄换供应商或区域。服务器只记录必要 metadata，请求体/图片不进入普通日志；遵循用户删除与存储保留策略。

## 月度订阅，不等于无限生图

套餐价格、月度单位、并发、存储、模型和模板权益均可配置并版本化。真实供应商成本单独核算，不把 One Hub 的固定单次收费当成商业成本真值。所有扣费/预留/释放都有 append-only ledger 和唯一幂等键。

第一版按月购买及手动续费，不承诺微信/支付宝自动扣费签约能力。可先管理员开通开发权益，真实付款路径未通过回调/幂等/对账验证前不得开放收费。已有 SDK 不等于已有生产就绪支付。

支付通知验签后核对商户、订单、币种、金额、最终状态。订单更新与权益发放在数据库事务内，使用唯一事件 ID 与状态 CAS；进程内 Mutex 无法保护多实例。重复和乱序通知仍返回支付商要求的正确 acknowledgement，但不得重复发放权益。退款/撤销需要独立状态和审计。

周期使用 UTC `[periodStart,periodEnd)`；自然月续费明确月末锚点与闰年处理。周期 unit 绑定 periodId，预留跨周期结算有确定策略，不能简单每月清零总余额。

## 迁移步骤

1. 只在开发/预发布数据库新增表，不破坏旧表/索引。建立可重复演练的 migration 和备份恢复脚本。
2. 旧用户 ID 保持稳定或建立明确映射；历史图片按 owner + legacyId 幂等迁移，校验 hash/数量/字节。
3. 浏览器 IndexedDB 中未同步图片必须提供导出/导入或旧版同步入口，不能误称“全在云端”并删除缓存。
4. 旧余额与兑换码单独保留。转换为月度权益前必须确认兑换政策，不能自动清零或按猜测汇率迁移。
5. 新旧 UI 双入口，V2 feature flag/灰度账号，拒绝长期无界双写。单项数据有一个明确权威源。
6. 回滚优先回滚路由/feature flag/worker 版本；已产生的新账本不能通过删表“回滚”。保存兼容读取或独立导出路径。

## 上线门槛

权限越权测试、任务重启恢复、支付重放/对账、素材私有访问、订阅到期与并发、图像质量样本、备份恢复和灰度回滚都通过。开源代码/模型权重/字体/模板的许可证分别核对；“rembg 是 MIT”不能推导所有权重允许任何商用。独立部署 GPL/AGPL 服务也不自动消除许可证义务。
