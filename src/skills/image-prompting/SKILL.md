# 生图提示词通用写法

目标：把用户的需求整理成清晰、可执行的提示词，再用 `create_image_task` 提交。让用户的意图更清楚，而不是替用户发明新内容。

## 1. 先判断两件事

1. **新图还是改图**：用户要在保留原图大部分内容的前提下改某处 → 编辑；用户给图只是参考风格、构图、氛围 → 带参考图的新生成；没有图 → 纯生成。
2. **一张还是一组**：一组变体要先确认张数和差异点。一个任务里的多张图共用同一提示词；内容需要不同时拆成多个任务。

## 2. 归类用途

先给请求归一个类，决定写法重点（每类的完整示例见 `references/use-cases.md`，需要时用 `read_skill_file` 读取）：

| 用途 | 写法重点 |
|------|----------|
| 自然写实照片 | 当作真实瞬间拍摄来写；用镜头、光线、景别语言；要真实纹理（皮肤毛孔、布料磨损）；避免影棚感 |
| 产品与包装 | 材质、轮廓、标签清晰；背景干净；图内文字需逐字给出 |
| UI 界面稿 | 先说保真度（可上线的界面 / 低保真线框），再写布局、层级、真实控件；不要用概念艺术词汇 |
| 信息图与图解 | 写清受众和阅读流向；逐个列出要标注的部件和文字 |
| Logo 与标志 | 简单、可缩放、轮廓强、负空间平衡；不加装饰 |
| 插画与故事 | 分格或分镜头写，每格一个具体动作 |
| 风格化概念 | 风格线索、材质、渲染方式（3D、厚涂、黏土）；不新增故事元素 |
| 历史场景 | 写明地点和时间，服饰、道具、环境符合年代 |

## 3. 补充多少细节

- 用户已经写得具体：只做整理和结构化，**不加**新的创意要求。
- 用户写得笼统：可以适度补充，但只补能明显提升效果的部分。

可以补充：构图和景别、用途和精致程度、实用的版式安排（如为文案留出区域）、支撑需求的合理场景细节。

不要补充：用户没暗示的人物、道具、物体；品牌名、口号、配色、剧情；没有依据的左右位置安排。

## 4. 分栏提示词模板

复杂需求用短标签分行，比一长段更可靠。只保留有用的行，可以加一行额外标签：

```
用途：<分类，如 产品图 / 网站头图>
资产类型：<用在哪里，如 落地页首屏、小红书封面>
主要需求：<用户的核心描述>
输入图片：<图1：角色；图2：角色>（有参考图时）
场景/背景：<环境>
主体：<主要对象及关键特征>
风格/媒介：<照片 / 插画 / 3D / 水彩…>
构图/取景：<近景 / 全景 / 俯拍；主体位置；留白>
光线/氛围：<光的方向、软硬、色温 + 氛围>
配色：<主色、辅色、点缀色>
材质/纹理：<表面细节>
图内文字（逐字）：“<准确文字>”
约束：<必须保留 / 必须遵守>
避免：<不想出现的东西>
```

顺序原则：场景 → 主体 → 关键细节 → 约束 → 用途。

## 5. 写法要点

- **写实**：直接写“写实照片”“真实摄影”，比堆相机参数更有效；参数只用来定大致的观感。
- **人物**：写清景别（“全身入镜，含双脚”）、视线（“看着书，不看镜头”）、与物体的互动（“双手自然握住车把”）。
- **把形容词换成可见事实**：“高级感”改成“哑光表面、低饱和暖灰、柔和侧光”；“氛围感”改成具体的光、雾、色彩。
- **图内文字**：放在引号里，说明字体风格、大小、颜色、位置；生僻词逐字拆开写；要求“只出现一次，不加其他文字”。
- **默认约束**：按需加“无水印、无多余文字、无真实品牌标志”。
- 不要写真实在世艺术家的名字或“××风格”，改为描述具体技法、色彩和构图。

## 6. 什么时候先问

只有关键信息缺失且会导致白花钱时才问，一次最多 2–4 个问题，并给出默认选项，例如：用途/尺寸比例、必须出现的文字、风格方向、张数。用户说“随便/你定”时直接按合理默认生成，并用一句话说明你的选择。

## 7. 提交参数

调用 `create_image_task({ prompt, inputImageIds?, params? })`：

- `size`：不确定可用尺寸时不填，使用用户当前设置；用户明确要横版/竖版/方图时再填。
- `quality`：草稿和快速探索用 `low`；小字、密集信息图、人像特写、需要交付的成品用 `medium` 或 `high`；不确定就不填。
- `n`：不填时按用户在输入框选择的张数；只有用户在消息里明确要求其他张数才填。不要擅自多生成。
- `output_format`：一般不填；需要后续抠图或保留细节用 `png`，要小文件用 `jpeg`/`webp`。
- 当前模型没有透明背景参数。需要“透明底”时，改为要求纯白或纯色背景、主体完整、边缘清晰，并告诉用户需后期抠图。

## 8. 迭代

- 先用干净的基础提示词出图，再每次只改一处（“光线更暖”“去掉多余的树”“恢复原背景”）。
- 每轮重复关键约束，防止漂移。
- 效果不理想时先问用户哪里不对，不要自行反复重跑。

## 提交前检查

- [ ] 判断了新图 / 改图 / 参考生成，参考图角色已写明
- [ ] 没有加入用户未暗示的人物、品牌、口号、配色
- [ ] 图内文字逐字放在引号里，并说明位置和字体风格
- [ ] 约束和“避免”项写清楚（水印、多余文字、品牌标志）
- [ ] 张数与用户要求一致；不确定的 size 留空
